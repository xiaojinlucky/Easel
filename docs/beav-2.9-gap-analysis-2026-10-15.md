**建议继续以 Meta 为主工作台。优先补齐创作过程中的关联、检索和修改体验。BEAV 作为已有的采集与运营辅助工具。**

> 后续实施状态（2026-10-15）：用户已选定第一批 2 → 1 → 3，并已在现役 7871 完成实现与界面验收。当前用法和证据见 [连续创作工作区](creative-workflow.md)。下文的“未实施”保留为本报告调研时点的历史状态。

本次问题的本质：让已有素材更容易变成能发布、能复盘的个人作品。衡量收益，应看少找几次文件、少复制几次内容、少重做几张卡片，以及能否接着上次写。

## A 先看结论与证据边界

### 最值得借鉴的三件事

1. **让每篇内容有连续的身份。** BEAV 已把原稿、平台版本与素材包放在一起。建议 Meta 进一步关联来源、选题、对话及发布记录。
2. **AI 围绕当前作品工作。** 引用哪条素材、修改哪一段、重做哪张图，都能明确指定。
3. **首页帮你决定今天做什么。** 推荐能接着执行，并回到同一篇作品。

这三件事直接服务你的个人写作。它们比再加模型入口、再建一套 Agent 框架更值得投入。

BEAV 的参考来自[稿件与发布](https://beav.pro/docs/workspace/drafts-and-publishing)、[对话工作区](https://beav.pro/docs/workspace/chat)和[运营日报](https://beav.pro/docs/workspace/daily-report)。Meta 实现范围由本地代码与实际需求决定。

## C 按性价比排序的开发清单

排序综合考虑：预计使用频率、对出稿的帮助、已有代码可复用程度、开发工作量和后续维护成本。频率属于定性判断；这不是实测收益分数。

人日是熟悉现有全栈项目的开发者的粗估，含必要验证。未做实施原型，误差可能超过一倍；各项有共用工作，不能直接相加。它不构成执行时间承诺。

| 排名 | 推荐板块 | 主要解决什么 | 增量工作量粗估 | 维护负担 / 性价比 |
|---|---|---|---|---|
| **1** | **连续创作卡与持久平台稿件** | 每篇作品关联素材、选题、会话、版本、排期、发布与复盘 | 4—8 人日 | 低至中 / **最高，核心基础** |
| **2** | **全文检索与多素材引用** | 让 523 条收藏的正文、转写、评论真正被找到和组合使用 | 2—4 人日 | 低 / **最高，最快见效** |
| **3** | **同屏创作与局部修改** | 少切页面，明确改哪段、哪一张卡，避免整篇重做 | 4—8 人日 | 中 / **很高，高频收益** |
| **4** | **今日创作台** | 给出一个值得写的题、一个可续写稿、待发与待复盘事项 | 2—4 人日 | 低至中 / **很高，依赖第 1 项** |
| **5** | **个人栏目模板与 IP 预设** | 把已有风格与图片变成可选择、可预览的稳定成品样式 | 2—4 人日 | 低 / **高** |
| **6** | **发布后复盘与指标快照** | 知道哪篇、哪个版本、什么时间的数据好，反馈下一篇 | 3—6 人日 | 人工录入低、自动采集中高 / **高但依赖发布量** |
| **7** | **BEAV 只读素材接入** | 在 Meta 选择和引用 BEAV 已采集的内容 | 1—3 人日 | 低至中 / **便宜，但当前数据增益小** |
| **8** | **可复用的内容拆解卡** | 将结构、切口、评论需求和可借鉴方法沉淀成有来源的材料 | 2—4 人日 | 低 / **中高，避免重复分析** |
| **9** | **少量对标账号更新** | 在固定的少数账号里发现新内容 | 手动 3—6 人日；自动化需另估 | 中高 / **有需求才提高优先级** |
| **10** | **风格反馈的确认与撤销** | 区分本篇修改、栏目偏好与长期个人风格 | 1—3 人日 | 低 / **中，现有锚点已较完善** |
| **11** | **常用媒体操作按钮** | 把转写、字幕或批处理从提示词变成稳定操作 | 2—5 人日 | 取决于已有后端 / **中低，按频率选两项** |
| **12** | **手机向 Meta 投递链接/媒体** | 降低手机收藏后转入电脑的操作量 | 2—4 人日 | 低至中 / **目前靠后，与飞书及 BEAV 重叠** |

**预算只够一批时：做第 2、1、3 项。** 第 2 项可以先交付；第 1 项为第 3 项提供稳定稿件身份。先让素材找得到、作品接得上、修改不重做。

**不要把“最便宜”当成“最优先”。** 第 7 项比第 1 项便宜，但 BEAV 当前空间只有 1 条知识记录。现成的本机素材网页已经能先用，桥接应随实际使用量增长再做。

**第 9 项可以条件性上调。** 如果你主要痛点重新变成“每天追踪固定博主”，它应升到第 4—5 位。按本次看到的存量素材与创作方式，先处理素材利用和连续创作更划算。

## D 前六项具体应该做到什么

### 1. 连续创作卡：解决作品各部分互相找不到

现状不是缺一张看板。`_ideas.json`、`_schedule.json`、文件状态和浏览器发布草稿分别存在。发布页“标记已发布”还会生成单独的记录键，未必对应原文件。

最小方案是给作品一个稳定标识，沿用现有文件目录。只新增缺失的关联和平台稿持久化。不要同时换数据库、重写内容库和重做日历。

```flow LR
素材引用 -> 选题: 支持观点
选题 -> 母稿: 开始创作
母稿 -> 平台版本: 适配正文与媒体
平台版本 -> 发布记录: 人工确认
发布记录 -> 复盘: 记录表现
复盘 -> 选题: 提供新问题
```

这里的箭头是推荐的关联关系，不表示 Meta 当前已经全部实现，也不表示自动发布。

作品页至少看见：来源、当前会话、最新母稿、各平台正文与媒体顺序、排期、发布链接、复盘。更改标题或移动文件后仍能找回同一作品。界面使用“这篇内容”“小红书版本”等词，不暴露内部 ID。

第一版验收：从一条收藏生成一个题，写成稿，保存小红书版；刷新页面后能接着修改。人工记下发布链接后，从复盘能回到当时的版本。修改新版本不能抹掉旧发布记录。

复用位置：[store.ts](../web/frontend/src/lib/store.ts)、[排期模型](../web/app.py)、[选题模型](../web/app.py)、[发布页](../web/frontend/src/components/PublishPage.tsx)。

### 2. 全文检索与多素材引用：用好现成的 523 条收藏

当前素材详情能看到转写和 OCR，但列表搜索不包含它们。会出现“我记得某个视频说过这件事，却搜不到”的落差。这个判断来自实际筛选代码。

最小方案：后端搜索最新快照的正文、转写、OCR 和评论；结果展示命中片段与来源。沿用当前收藏主源，不回写飞书。现有规模先用普通文本检索，不引入向量数据库。

接着加手选引用：选 2—5 条，发送时显示引用卡片。Agent 按记录 ID 读取原文。创作卡记录哪些素材用于哪篇稿，帮助避免反复推荐同一来源。

“使用记录”是本报告为 Meta 提出的增补，不能据此声称 BEAV 已具备完整的引用关系图谱。

第一版验收：只出现在转写中的词能被搜到；点击命中片段能打开对应素材；两条同名素材不会混淆；没有正文时明确显示缺失。现有排序和单条“拿去写”继续可用。

复用位置：[MaterialsPage.tsx](../web/frontend/src/components/MaterialsPage.tsx)、[现有画像评分](../web/meta_recommend.py)、[Feishu 数据入口](../web/app.py)。

### 3. 同屏创作与局部修改：提高最后一公里效率

Meta 已能显示产物。真正值得学的是，让预览持续停留在当前作品旁边，并将修改目标准确传给 Agent。

第一版只做文字稿与文字卡：左侧讨论，右侧当前稿和卡片预览。允许选一段文字要求改写，或选择第 2 张卡只重渲这一张。保存新版本，并提供修改前后查看与撤回。

沿用现有渲染器和文件输出。暂不做全功能富文本编辑器、浏览器工作台、自由画布或视频时间线。Word 手改稿继续只读，新建议另存。

第一版验收：只改第 2 张卡时，其余卡片文件不变；刷新后仍打开同一作品；选区过期时先提示重新选择；用户能看到原稿并恢复。

复用位置：[ArtifactGallery.tsx](../web/frontend/src/components/ArtifactGallery.tsx)、[内容库续写入口](../web/frontend/src/components/OutputsPage.tsx)、[文字卡渲染器](../skills/builtin/text-to-card/render_card.py)。

### 4. 今日创作台：少量、可执行、有证据

不需要先复制一套每天 09:00 的后台日报系统。第一版在打开首页或点击更新时生成即可。

首页保留四类内容：一个推荐选题、一篇可续写稿、待人工发布的稿件、到期复盘。每条说明依据，展示来源和更新时间，并跳回对应作品。

选题可以复用现有画像评分和漫步技能。没有适合素材时显示原因；没有发布记录时不编造昨日复盘。待办完成不能自动视为平台发布成功。

第一版验收：从推荐题开始创作后，回到首页可续写同一会话；刷新不重复建立选题；人工放弃有记录，原文件保留。

复用位置：[DashboardPage.tsx](../web/frontend/src/components/DashboardPage.tsx)、[calendar_ops.py](../skills/shared/scripts/calendar_ops.py)。

### 5. 个人栏目模板：让现有能力可直接选用

建议先做 3—5 个常用栏目预设。候选可以是论文解读、科研避坑、工具实操、方法对照；具体名称由真实发文记录决定。

每个预设展示一张你自己的完成样例，说明需要的材料。保存页面结构、字号层级、封面方式、IP 资产组合和内容检查项。已有 IP 图和文字卡先用起来，不依赖收费生图接口。

模板服务你的语气。继续以原文锚点为准，不把 BEAV 的模板文案、图标、示例图或通用“爆款腔”复制进来。

第一版验收：同一栏目第二次使用无需重新描述格式；更换正文不会换掉个人风格；缺少必要图片时不生成假占位成品。

复用位置：IP 资产说明（本机记录，未公开）、Meta 工作台规则（本机记录，未公开）。

### 6. 复盘：先把已发布作品和真实反馈接起来

已有人工复盘表、发布分析脚本，第一版不需要再接一个收费数据服务。每篇作品保存平台链接、发布时的版本，以及带采样日期的指标。

先允许手动录入或导入用户导出的数据，再考虑复用已有创作中心采集。比较同平台、相近发布时间的作品；没有历史快照时不展示增长速度。

复盘保留用户判断：读者卡在哪里、哪条评论值得继续写、哪句话需要保留。它可以提出下一篇选题，但不能因一次数据好就自动改写长期风格。

第一版验收：缺数据与零值分开；一次复盘能打开对应成稿；更正数据保留采样时间；人工填过的信息不会被失败的刷新覆盖。

复用位置：[现有复盘与下一篇提示](../web/frontend/src/components/OutputsPage.tsx)、[分析脚本](../skills/builtin/skill-publish-analytics/scripts/analyze.py)。

### 第 7 项的最小接法

## F 哪些应该暂缓，为什么

| 暂缓项目 | 不优先的具体原因 | 保留的最小替代 |
|---|---|---|
| 完整视频编辑器 | 时间线、字幕、音画同步、撤销和导出一起维护，远超一个按钮的成本 | 先用现有脚本和已有剪辑工具走通一种视频产线 |
| 通用 Mini App 平台 | 沙箱、权限、版本、任务与 SDK 都成为长期维护责任 | 给高频操作做普通表单 |
| 视频节点画布 | 当前收益依赖稳定视频需求；还容易引入付费生成 | 先保留固定步骤的脚本与必要重试 |
| 新 Agent 编排系统 | v030 已有多底座与会话恢复；重复投入会分散维护 | 补实际缺失的作品上下文传递 |
| 全平台全天候自动盯号 | 登录、验证码、限频、内容字段变化和费用都持续发生 | 3—5 个账号，人工触发，记录每次真实成功 |
| 泛热点大屏 | 已有入口；热门不等于适合个人账号，也不等于正在增长 | 在“今日创作台”给有来源的少量选题 |
| 全自动写作并发布 | 违背现有人工发布决定；文档也未证明可无条件稳定执行 | 制作完整发布包，人工检查与发布 |
| 自动改写长期记忆 | 单篇编辑意见可能只是本次需要；错误会污染后续写作 | 明确选择仅本篇、栏目或长期偏好，并可撤销 |
| Eagle 深度接入 | 是外部产品依赖，当前没有必要增加购买成本 | 复用现有 IP 资产目录与媒体选择器 |
| 远程服务与团队多租户 | 本次是个人本机工作台，尚无多人或跨机协作瓶颈 | 维持现役本地入口 |

本节不是判断 BEAV 的这些功能不好，而是按你当前任务与现有资产衡量投入。若工作重心转为持续视频生产，视频能力需要重新排位。

### 三批推进

| 批次 | 范围 | 本批真正的完成条件 |
|---|---|---|
| 第一批：找得到、接得上、改得快 | 第 2、1、3 项 | 一条真实收藏成为稿件；跨页和重开后可续写；局部修改不重做其他部分 |

- 飞书快照继续只读，旧收藏保留原来源。

- 空内容、重复点击、刷新中断和旧版本恢复在真实入口验收。

以后判断开发是否划算，可以记录找素材耗时和首稿操作数。再记录局部修改重做页数，以及跨会话续写成功率。先记录现状，再比较改动后的结果；本报告没有捏造这些基线或收益数字。
