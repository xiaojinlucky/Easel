### 商业版真正执行的机制

```mermaid
flowchart LR
  A[主页链接与账号预览] --> B[确认创建账号空间]
  B --> C[采集单页候选并选择五条]
  C --> D[保存账号与笔记并逐项读回]
  D --> E[生成定位与协作档案]
  E --> F[生成写作风格与候选记忆]
  F --> G[新对话读取定位和风格]
  G --> H[保存并回读本地草稿]
```

1. **先识别，再建空间。** 主页解析返回账号预览，确认创建才写入账号空间；解析成功不等于已经完成建档。
2. **样本选择有明确口径。** 客户端代码对小红书使用点赞、B站使用播放、公众号使用发布时间；本次实际运行的是小红书的单页 20 选 5，不是全平台实测。
3. **先保存证据，再诊断。** 本次账号、五条笔记及证据引用可读回后，自动启动定位生成；不是只把主页 URL 交给模型猜测。
4. **基础可用与增强分开。** `CreatorProfile.md`、`Soul.md`、`user.md` 先完成；随后写入 `style-profile.json` 和账号专属 `writing-style/SKILL.md`。父任务负责风格，两路只读子任务提取记忆和资产候选。本次记忆保存成功，资产候选为空，没有伪造资产。
5. **创作实际消费档案。** 后续会话 `session-1789023464235` 两次读取 `profiles://creator_profile`，成功加载并读取本空间 `writing-style/SKILL.md`。没有独立证据证明 Soul、user 和 style-profile.json 在这一轮全部隐式注入，不作该断言。
6. **文件与业务稿件不同。** 自动创作结束时草稿写入空间根目录并回读，但`manuscripts`为空，工具记录没有登记稿件的动作。原生聊天预览显示“文件不存在或已被移动”，独立读回磁盘文件仍存在、3470字节且哈希一致；UI路径显示 `Administrator.redconvert`，与真实 `Administrator/.redconvert` 不同。只能定位为本次文件交接失败，尚未确认路径改变发生在哪一层。
7. **稿件提供平台版本容器。** 随后的独立手动验收从“新建长文”进入，改名并粘贴本次商业版公开草稿部分，稿件目录真实保存2172字节，原生预览通过；同一稿件有原稿、公众号、小红书、口播稿入口。未生成平台素材包时显示“素材包不可用”，发布按钮禁用。此结果证明手动稿件流程可用，不把它回填成上一轮AI自动交接通过。

机制证据：`.runtime/acceptance-20260910/mechanism/` 中的 `source-hashes.json`、`static-evidence.json`、`runtime-observation.json`、`profile-hashes.json`、`final-state.json`、`account-source-evidence.json` 和 `creation-verification.json`。静态材料只用于学习客户端契约，未复制商业代码或恢复私有服务端算法。
